# 设计笔记

> 为什么是现在这个样子。写给想改代码的人，也写给几个月后的我自己 —— **做过一轮取舍**的地方，把理由留下。

## 一、三条不动的原则

1. **本地优先**：数据只在一个 SQLite 文件里，没有账号、没有服务端、不联网。可验证 —— 全仓库没有任何 HTTP / socket 调用（`SECURITY.md` 里有自查方法）。
2. **一个文件就是全部**：任务、排程、序列、模板、成就、设置都在同一张库里（12 张表）。所以「导出备份」是一个一致副本，「拷到 U 盘」就是便携。
3. **能撤销才算安全**：所有会动数据的操作都走**命令层**，写之前拍一份快照 —— `Ctrl+Z` 能退回去。唯一的例外是成就（`achievements` 表**刻意不进**快照：撤销不该把勋章收回去）。

## 二、数据模型

```text
tasks            任务（名字、分类、预估时长、层默认、⊘ 不计入、排序、归档标志）
blocks           排上的块：task_id（可空 = 临时安排）、起止、层、label、repeat 标记、通知水位
sequences        序列（一串有先后的块）
sequence_members 序列成员（含顺序）
repeats          每周重复规则（周几 + 时刻 + 层）
repeat_occurrences 水位线（这一周已经生成过 → 幂等，不重复生成）
templates        模板（某一周的骨架：层 / 时段 / 时长 + 名字 + 分类）
reviews          周复盘（备注等）
events           事件流水（成就与统计读它 —— 它们只能从流水里算，不能自己写状态）
external_blocks  外部块（导入/展示用）
achievements     成就（唯一不进撤销快照的表）
settings         设置（白名单键，非法值不落库；见下）
```

几条纪律：

- **迁移只追加**（`src-tauri/migrations/001…011`），历史迁移永不修改 —— 老库升级靠顺序重放。
- **`settings` 不是通用键值库**：只有白名单里的键能读写，值要按键校验（布尔只认 `0/1`、预算 60–1440 分钟、JSON 过结构）。写错键名会报错，而不是静默塞垃圾。
- **派生字段不进库**：例如块上的 `🔁` 标记是查询时算的，不同步存，避免两处漂移。
- **每张表都有随包迁移的读者**：`SNAPSHOT_TABLES` 与恢复时的删除顺序有一一对应关系，有单测看守。

## 三、时间轴

- 一周 = 7 天 × 48 格（每格 30 分钟）；块落在格上，拖边缘按 15 分钟步长改时长。
- **融合**：同一任务相邻的块自动接成一块 —— 少一个「两块之间差 5 分钟」的脏状态。
- **残影**：块被挪走 / 删除后，原位置留一道浅色记号（有寿命），让你知道「刚才这里有什么」。
- **跨周**：块跨越周日午夜时，在相邻两周里各渲染一段，数据仍是一行 —— 而不是拆成两行再想办法合并。
- **漂流**：没排上的任务由「漂流卡」来问，而不是在列表里躺着变旧。「自己安排」复用拖拽预览那条链路。

## 四、提醒

按「会被打断的程度」分层，而不是一个开关管全部：

- **开始提醒**：到块开始时刻说一句；可以提前 5 / 10 / 15 / 30 分钟。
- **结束提醒**：问「完成还是未完成？」—— 通知上直接带按钮，答案落库（这一步产出的 `complete` 事件是统计与成就的源）。
- **免打扰**：暂停 30 分钟 / 2 小时 / 到明早。静音期间**不发、只静默记账**；解除后不补发一串（补发只会变成噪音）。
- **复盘提醒**：默认**什么都不做** —— 默认值应该礼貌，不能替用户决定「我要被催」。
- **计划任务兜底**：默认**关**。打开才在 Windows 任务计划程序里注册（应用没开也能提醒），关掉即注销；单实例、避免和正在运行的窗口抢。
- 托盘四态（当前任务 / 超载 / 闪烁 / 静音）只是这套提醒的可见面。

## 五、复盘与统计

- **重叠只算一次**：一天的「占用」按时间**并集**算，不是各块时长相加 —— 否则并排安排会被算成两倍。
- **`⊘ 不计入`**：临时块级的例外、任务级的长期例外；它同时影响精力条、复盘与统计（一个口径）。
- **预算**：每天一个可调预算（默认 6 小时），超了当天小条变红 + 顶部提示 + 托盘红环。
- **成就只能读流水**：98 条成就全部由 `events` 推算（没有一个能自己写状态）—— 这样「成就说的事」和「统计说的事」永远同源。

## 六、外观系统（设计令牌）

三层，从上到下：

```text
src/lib/styles/tokens.css     原始令牌（颜色 / 间距 / 字号 / 字距 / 圆角 / 时长）
       ↓ 由生成器派生
src/lib/styles/palettes.css   12 套配色的语义令牌（亮 / 暗各一套）+ 9 套装饰（底纹 / 边框 / 展示字）
       ↓ 组件只用语义变量
组件里不写字面颜色 / 数值
```

- **生成而非手写**：`tools/visual/gen-palettes-85.mjs` 是配色的唯一生成器（源在 `tools/visual/candidates/decor-86.json`），`--check` 保证生成物与源逐字节一致 —— 手改 `palettes.css` 会被拦下。
- **两把尺子**：`spacing-audit.mjs`（间距 / 字号 / 字距 / 密度刻度三方对齐）与 `contrast.mjs`（24 组 × 52 对颜色对比度，含淡化带）—— 审美靠人，**可测量的部分交给机器**。
- **可调 vs 直接改**：有分歧余地的（配色 / 深浅色 / 密度 / 字号 / 字体族 / 12–24 制 / 日期格式）做成设置项并给推荐默认；有明显对错的（对比度不足、术语不统一）直接改，不给开关。
- **字体**：界面字体族五档（只换中文字形，拉丁与数字仍走系统栈），展示字是随包的四款开源字（SIL OFL 1.1，无 CJK，中文自动回退系统字体）。

## 七、多语言

`messages/zh.json` 是**唯一源**；英文表由工作表流程构建（`tools/i18n/en-build.mjs`：按值翻译 + 按键例外），`tools/i18n/check.mjs` 是机器判据：

- 源码里不该再有用户可见中文硬编码（含插值表达式里）；
- zh ↔ en 键齐、占位符一致、英文无中文残留；
- 术语表与文案规范（省略号、空格、情态词、禁用词）机械扫描。

所以「改文案」的入口只有一处；英文不是手抄的第二份。

## 八、数据安全（为什么它敢让你关掉窗口）

- **恢复前先留副本**：从备份恢复前把当前库改名成 `.before-restore`；便携模式切换位置时把被覆盖的一侧改名成 `.before-switch`。**只复制、从不删**。
- **不碰正在使用的那份库**：复制方向永远是「正在用的 → 重启后会读的那一侧」，避免 Windows 下改一个正被 SQLite 打开的文件。
- **启动完整性检查**：库坏了会明确告诉你，而不是安静地给你一个空界面。
- **便携目录要能写**才算便携（写完探测文件立刻删）；写不进去就回落默认位置并说明原因，不把你的数据卡在一个只读目录里。

## 九、工程上的几条硬规矩

- **修 bug 先复现**：先写一条会失败的检查（Rust 单测 / vitest / 预览断言），再去改代码让它变绿。写不出复现就先别改。
- **界面验证用假数据**：`tools/preview/` 启动真前端 + 假后端跑 DOM 断言与截图（见 `CONTRIBUTING.md`）—— 从不用真实数据做验证。
- **规模**：目前 26 个 Svelte 组件（约 1.4 万行）+ Rust 后端；`cargo test` 414 条、vitest 347 条、界面断言 397 条 + 真输入探针若干，全部随提交跑。
- **发布**：版本号一处一改（`package.json` / `Cargo.toml` / `tauri.conf.json` / `package-lock.json`）→ 出 MSI → 校验值随 Release 发布（见 `CONTRIBUTING.md`）。

## 十、刻意不做的

| 不做 | 为什么 |
| --- | --- |
| 云同步 / 多端 | 有了账号就有了服务端、隐私边界与运维；这个工具的价值恰恰是「不依赖任何东西」。想跨设备就导出备份 / `.ics`。 |
| 账号 / 登录 | 同上；没有账号就没有「找回密码」。 |
| 代码签名（暂时） | 证书要花钱；先如实说明 SmartScreen 提示怎么处理（README 里写了）。等真有人被吓退再说。 |
| 遥测 / 崩溃上报 | 与「不联网」冲突。 |
| 插件 / 主题市场（暂时） | 主题包的格式与安全边界要先想清楚（不能执行代码、不能越界读文件），宁慢不乱。 |
